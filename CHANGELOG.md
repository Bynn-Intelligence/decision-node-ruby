# Changelog

All notable changes to this gem are listed here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the gem uses
[Semantic Versioning](https://semver.org/).

## [0.3.0] - Unreleased

Implements version 1.3 of the DecisionNode SDK surface (`DecisionNode::SPEC_VERSION` is `"1.3"`): boosters and fine-tuned models.

### Added

- Boosters: `boosters:` on `decide`, `check`, `classify`, `score`, `number`, `gate`, `decide_many` requests, batch requests and `check_request`, taking names (`"age"`), `DecisionNode::Booster.new(name, images:, require:, options:)` or wire-form Hashes, sent in the order given; a `Booster` is sent as `{"name" => ...}`, each argument only when given, or as the bare name when none is. Without boosters, or with an empty Array, the request has no `boosters` field. Nothing about boosters is checked before sending, except that their options count toward the nesting limit. Sessions take no boosters.
- `Decision#evidence`: booster name to `DecisionNode::Evidence` (`version`, `status`, `latency_ms`, `billed_calls`, `results`, `raw`) in the request's order, `nil` for a request without boosters. Readings are `AgeReading` (`image`, `faces`, `age_years`, `low`, `high`, `confidence`), `AiGeneratedReading` (`image`, `generated`, `confidence`, `method`, `top_generator` as a `TopGenerator` with `name` and `probability`, `nil` unless the reading says likely generated, `c2pa_signer`, and `c2pa`, `"untrusted"` for Content Credentials that validate but are not trusted) and, for a booster this version does not know or a reading with a field missing or of the wrong type, `UnknownReading` with its `raw` fields; a reading never fails the decision. A batch result's decision has them too.
- `usage.booster_tokens` and `usage.boosters`, `nil` when the response has none.
- `usage.cost`: what the answer cost, a `DecisionNode::Cost` (`usd`, `model_usd`, `boosters_usd`, `free_tier`), read as sent and never summed; `nil` when the response has none. Decisions, batch result lines and session frame replies carry it.
- `DecisionNodeError#boosters`: the `x-decisionnode-boosters` header as booster name to `DecisionNode::BoosterStatus` (`status`, `latency_ms`), in the request's order; an empty Hash when there is none.
- Fine-tuned models: a fine-tuned model's name (`decisionnode-moe@acme/fraud`, or pinned with `:3`) is sent as given, and `Decision#model` is the pinned name that answered. `ModelInfo#fine_tuned`, `#base`, `#adapter_version` and `#status` (and `fine_tuned?`), `nil` on a catalogue model.
- `RequestTooLargeError`, for the API's 413 on any call (never retried) and raised before sending when the encoded body is over 26,214,400 bytes (25 MiB), the API's limit: on `decide`, the helpers, `decide_many` (for the whole call, before anything is sent), each batch line as sent and `check_request`. An image that would be uploaded counts by its upload id, so nothing is uploaded to measure. `decide_raw` sends its body as given.
- Several places in one answer: `DecisionNode.point` and `DecisionNode.box` take `max:` (sent only when given), and such a question is answered with a `DecisionNode::PointsAnswer` or `DecisionNode::BoxesAnswer` (`count`, `present`, `complete`, `points` or `boxes` with their own `confidence`, `image`, `width`, `height`), told apart by the answer's own list, so batch results read the same; one with a field missing or of the wrong type is an `UnknownAnswer`. `max:` that is not an Integer from 2 to 16 raises a `ValidationError` before sending; whether a model version answers several places is the API's to say.
- The fallback: `fallback:` (`true` or `false`, sent only when given) on `decide`, the helpers, `decide_many` requests, batch requests and `check_request`; any other value is an `ArgumentError`. `Decision#fallback` is a `DecisionNode::Fallback` (`served_model`, `requested_model`) from the `x-decisionnode-fallback` and `x-decisionnode-requested-model` headers when another model answered in place of the one asked for, `nil` otherwise; a batch result's decision reads them from its line's headers.
- An image id longer than 64 characters (counted in characters, not bytes) raises `BadRequestError` (`api_usage_error`, "Image 1: its id is longer than 64 characters.") before anything is sent, after the empty-id check and before the duplicate check.
- Readings of the `face_detection`, `face_recognition` and `ocr` boosters: `FaceDetectionReading` (`faces`, `detections`, each a `FaceDetection` with a `FaceBox` and a `confidence`), `FaceRecognitionReading` (`faces`, `matches`, each a `FaceMatch` with a `FaceBox`, a `score`, the `collection` searched, the item's `reference`, and `name` or `label`, nil when absent) and `OcrReading` (`text`, `truncated`). Box corners are kept as sent, pixels or fractions; a reading with a field missing or of the wrong type is an `UnknownReading`.
- Collections of faces, `dn.collections`: `create(name:, type: "face")`, `list`, `get`, `delete`, `enroll(collection_id, image:, reference:, label: nil)` (the image sent as a decision sends one), `list_items(collection_id, offset:, limit:)` and `delete_item`, each returning the API's object as sent. `create` and `enroll` send an `Idempotency-Key`, a new UUID for each call and the same on every attempt of it, so the API creates, enrolls and bills once however often the call is tried; they retry as every call does, and also on a 409 `idempotency_in_progress` after its `Retry-After`, while a 409 `idempotency_key_reused` is raised. Reads and deletes carry no key. The name (1 to 80 characters), the reference (1 to 64 of `A-Z a-z 0-9 _ . : -`, an empty one failing the pattern), the label (at most 128), the paging and an image URL's rules are checked before sending, with the API's `ValidationError` or `BadRequestError`; any other fault of the enrolled picture is the API's 422 `image_unreadable`.
- A decision whose boosters name `ocr` waits 30 seconds per attempt when the client has no `timeout:` of its own (a timeout you set is used as given), and is never retried after a timeout, since the server finishes that attempt and may bill it. Its other retries stay.
- The README documents boosters, how they are billed and their errors, fine-tuned model names and the fallback.

### Changed

- A 403 whose `error_type` is not `refusal_error` (`booster_not_enabled`, a suspended workspace) is a `PermissionDeniedError`, as before; a 529 `booster_unavailable` is an `OverloadedError`, retried like every 529.
- An error whose body is not JSON (a page from a proxy or the service's edge, or no body) is classified by its status alone, with `error_type` `nil`, and its message is `HTTP <status> <text>` from a fixed table (`HTTP 413 Content Too Large`), followed by the request id when the response has one. The body is no longer kept on the error.
- The default model is `decisionnode-moe`, the family id of the main model (it was `decisionnode-latest`), and the documentation uses the family ids `decisionnode-moe` and `decisionnode-flash`. A pinned id is `decisionnode-<family>-<version>`, its version from `models`; the older ids are still accepted by the API and sent as given.

## [0.2.0] - Unreleased

Implements version 1.2 of the DecisionNode SDK surface (`DecisionNode::SPEC_VERSION` is `"1.2"`): sixteen images a request, videos sent as frames, and point and box questions.

### Added

- Videos sent as frames: `DecisionNode::Video.new(id, frames:, fps:, start:, end:)` and `DecisionNode::VideoFrame.new(t, data:)`, `VideoFrame.new(t, path:)` or `VideoFrame.new(t, base64:, media_type:)`. A frame's media type comes from its bytes when none is given. `fps`, `start` and `end` are sent only when given. A Hash in the API's wire form is accepted wherever a `Video` or a `VideoFrame` is.
- `videos:` on `decide`, `check`, `classify`, `score`, `number`, `gate`, `decide_many`, batch requests and `check_request`. Frames are always sent inline as base64: never uploaded, never cached and never counted toward `inline_threshold`. Sessions take no videos.
- The API's video form rules checked before sending, in its order and words, as `BadRequestError` with `error_type` `api_usage_error`: an id, ids unique across images and videos, a non-empty frame list, frame times of at least 0 and increasing, a JPEG, PNG or WebP media type, `fps` above 0 and at most 4, `start` and `end` at least 0, and `end` after `start`. Frame counts, a frame's bytes and the window are left to the API.
- Point and box questions: `DecisionNode.point(instructions, image:, units:)` and `DecisionNode.box(...)`, answered as `PointAnswer` (`x`, `y`) and `BoxAnswer` (`x1`, `y1`, `x2`, `y2`), each with `present`, `confidence`, `image`, `width` and `height` as sent; an answer with a field missing or of the wrong type is an `UnknownAnswer`. They go with `decide`, `decide_many`, batch requests and `check_request`. Checked before sending as the API would: a request without an image, a missing or unknown `image`, and `units` other than `pixels` and `normalized` raise a `ValidationError` with the server's entries, and a question without instructions a `BadRequestError`.
- `Decision#usage.video_frames` and `usage.video_seconds` (nil when the response has none) and `Decision#warnings` (each sentence as sent, an empty Array when none), also on batch results.

### Changed

- Up to 16 images a request (4 before) and up to 4 videos, checked before sending: more raise the API's `ValidationError` with a `too_long` entry on `images` or `videos` (`ctx.max_length` 16 or 4), listed with the request's other 422 entries after the state's and the questions'. Its `input` is the list in its wire form, a local image as its id and media type without its bytes. A lower image limit held from `models` (on the entry, else in its `images` object) is checked the same way.
- `upload` takes 1 to 16 images a call; more raise the API's `BadRequestError` (`api_usage_error`) before anything is sent.
- One `POST /v1/uploads` takes up to 16 files.
- The conformance tests run suite 1.10.

## [0.1.0] - Unreleased

First version, implementing version 1.1 of the DecisionNode SDK surface: every public call of the API.

### Added

- `DecisionNode` client with `decide`, `decide_many`, `check`, `classify`, `score`, `number`, `gate`, `models`, `upload`, `open_session`, `supervise`, `batches`, `run_batch` and `decide_raw`. `check`, `classify`, `score`, `number` and `gate` take `images:` and `model:` like `decide`.
- `number` questions: the builder `DecisionNode.number(instructions, min:, max:, step:)`, which leaves out a bound not given, the `number` helper, and `NumberAnswer` with `number`, `expected`, `confidence` and `probabilities` keyed by the value as the server wrote it.
- Images by URL, path, bytes, base64 text, an IO or an upload id. URLs pass through after a local check (`https`, at most 2,048 characters) and are the recommended form. Local images go inline when a request's local images total under `DEFAULT_INLINE_THRESHOLD` (524,288 bytes; the `inline_threshold:` option), otherwise they are uploaded once (one `POST /v1/uploads`, parallel `PUT`s with exactly the returned headers) and sent by upload id. An in-memory cache by SHA-256 reuses an upload whatever the size until 5 minutes before it expires, concurrent calls with the same bytes share one upload, an upload the API reports stale is uploaded again and the request sent once more, and a PUT refused with 403 after its URL's 5 minutes is presigned again once. Upload URLs and cache entries are judged by the client's clock. `upload(images)` uploads explicitly.
- Every fixed rule the API documents is checked before any request and raised as the server would answer it: the same class, the same `error_type` (null for the API's plain-string 400s and its 422s, `api_usage_error` for images, unknown types, nesting, frames and batch fields, `image_url_refused` for refused URLs), the documented message, and for a 422 the server's `entries`. Covered: the 128-level nesting limit, question types and field types, choice and score counts, truth and number instructions, number grids (types, 2^53, decimals, the decimal bound, order, 4,096 values) counted in exact decimals, images (count, ids, format from the magic bytes, 10,485,760 bytes, 40,000,000 pixels read from the JPEG, PNG or WebP header, upload references, URL form, port, user information and literal private addresses), session `window` and `ttl_seconds`, frames refused by `Session#send` before anything is written or a `seq` is used, `custom_id` rules, an empty add and `batches.list` paging. Limits only `/v1/models` states are checked once `models` has been called.
- Sessions: `open_session`, `Session#connect`, `#send`, `#replies`, `#next_event`, `#end` and `#close`, with `Reply`, `FrameError` and `SessionClosed` values, `seq` counted from 1, pings answered, a silent socket treated as lost, and `supervise`, which reopens or reconnects by close code with a capped backoff. A session limit raises `SessionLimitError`, a `RateLimitError`, and is never retried.
- The Batch API: `batches.create`, `add` (split at 10 MiB), `finalize` (a 409 resolved with `get`), `get`, `list`, `results` and `cancel`, with `Batch`, `BatchPage` and `BatchResult`; create, add and finalize retried only on 429 and 529. `run_batch` runs the whole lifecycle with a poll interval of at least 10 seconds, the server's `Retry-After` when longer, and a timeout.
- `ModelInfo#sessions`, `#batch` and `#limit` for the limits `GET /v1/models` publishes.
- `check_request(method, request)` and `Session#check_frame`: every local check of a call, run alone; they raise what the call would raise and send and upload nothing. A model's held `/v1/models` limits are found by its name, else by an entry's `alias` or pinned `version`.
- `upload_timeout:` (default 60 seconds): each image `PUT` to storage has its own timeout, apart from the API's `timeout`.
- `batches.results` reads the JSON Lines file from the network line by line (`NetHTTPTransport#stream`), however many lines it has, and takes a block to handle each result as it arrives.
- A session's socket goes through the transport's proxy (else the environment's) with a `CONNECT` tunnel and takes its `net_http:` TLS settings, such as a company CA (`NetHTTPTransport#session_options`).
- `gate` with fixed question wording, the same in every DecisionNode SDK.
- `decide_many` returns one `DecisionResult` per request, a `Decision` or a `DecisionNodeError` (an unexpected error is wrapped in `DecisionNodeError` with the original as its `cause`). Every request is checked before any is sent: a `concurrency` below 1 or any invalid request raises `ArgumentError` and nothing is sent.
- `check`, `classify` and `score` raise `ServerError`, with `status`, `request_id` and `reason`, when their own answer is missing or malformed; `decide` returns it as `UnknownAnswer`.
- Question builders `DecisionNode.truth`, `DecisionNode.choice` and `DecisionNode.score`, also available through `include DecisionNode::Questions`.
- Typed answers: `TruthAnswer`, `ChoiceAnswer`, `ScoreAnswer`, `NumberAnswer`, and `UnknownAnswer` for answer types this version does not know. `models` returns `ModelInfo` entries. Missing token counts and latency are `nil`.
- `DecisionNode::Image`: the media type is taken from the first bytes (JPEG, PNG or WebP). A file is read when the `Image` is made; an unreadable one raises `ArgumentError` there, and bytes in another format raise `BadRequestError` before any request.
- The safety check result as `decision.safety`.
- Retries with `retry-after-ms`, `Retry-After` in seconds or as an HTTP date (server waits capped at 60 seconds) and exponential backoff.
- A timeout that covers the whole attempt, from sending the request to the last byte of the body, with any transport.
- Argument checks when the client is made: `base_url` must use `https` (`http` only for `localhost`, `127.0.0.1` and `::1`), `timeout` must be above 0 and `max_retries` 0 or more. Bad arguments raise `ArgumentError`, never a DecisionNode class; an empty question map, an unreadable image file and a value that cannot be serialised do too.
- An answer of a known type with a missing or wrongly typed field is returned as `UnknownAnswer` with its raw fields.
- `NetHTTPTransport` keeps connections alive per host (`max_idle:`, `keep_alive_timeout:`) and takes `proxy:` and `net_http:` (Net::HTTP settings such as `ca_file`). Settings that could turn TLS or certificate checks off (`use_ssl`, `verify_mode` other than `VERIFY_PEER`, `verify_hostname: false`, `verify_callback`) are refused, and TLS with peer and hostname checks is set again after the caller's settings for an `https` URL. A transport passed as `http_client:` must answer `false` to `follow_redirects?` or it is refused, and a response from another address than the one requested is an error.
- The README documents the `x-decisionnode-safety-body` request header.
- Errors: one class per documented status, `PermissionDeniedError` for a 403 that is not a refusal, and the base `DecisionNodeError` with its status for any other status. Only 2xx is a success and redirects are never followed. An error's `message` is the server's message, an empty string when it sent none. There is no second name for the base class.
- `DecisionNode::SPEC_VERSION`, the version of the SDK surface this gem implements (`"1.1"`), and `DecisionNode::DEFAULT_INLINE_THRESHOLD`.
- Configuration through `DECISIONNODE_API_KEY`, `DECISIONNODE_BASE_URL` and `DECISIONNODE_MODEL`; an empty argument counts as not given.
- Optional debug logging that never prints state, questions or answers.
- The conformance tests fail, never skip, when `DECISIONNODE_CONFORMANCE_DIR` is not set. CI runs conformance suite 1.6 at a pinned commit, with every action pinned to a commit SHA and `persist-credentials: false` on every checkout.
